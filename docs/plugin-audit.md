# 厦大 PPT Master 插件审查

审查日期：2026-10-31。范围：技能入口、两条厦大工作流、14 套模板资产、导出入口与生成后质检。

## 判断

具备可用的厦大模板与可编辑 PPTX 引擎。此次修复后，已验证的资产和导出链路可以使用；尚不能承诺任意主题均无需人工检查即可得到演讲级成稿。本仓库是供 AI Agent 使用的 Skill，并非独立运行的主题生成服务。

## 已修复

| 问题 | 处理 |
| --- | --- |
| 原生填充声称支持全部 14 套，实际缺少南强蔚蓝源文件 | 明确 14 套 SVG、13 套原生填充；生成前检查能力，不推荐缺失路径 |
| scaffold 使用 set，导致重复页丢失、顺序被还原 | 按用户给定序列建立独立填充项（含图表嵌套数据）；不存在的页码报错 |
| SVG 导出失败被入口脚本吞掉退出码 | 透传 main 的退出码，自动化可正确拦截失败 |
| 质检漏查组合形状、表格里的占位符 | 扫描完整页面段落，支持中文及小写占位符、跨 run 文字 |
| 越界检查只查左右 | 同时检查上下边界 |
| 厦大快速流程与上游多轮确认冲突 | 明确厦大路线优先级，只有主题时默认直接出 SVG 稿；区分上传材料和用户指定原生模板 |
| 章节和正文文件名前缀导致播放顺序错乱 | 按实际演示顺序连续编号，章节页与内容页交错 |
| 仅给主题可能被补成虚构研究结果 | 默认生成方案或知识稿，禁止编造数字、引用、身份信息 |
| 只复制 SVG 可能丢失图片；标识缺少明确约束 | 要求复制相对路径素材，复用真实 Logo，检查可见性与比例 |
| 正文字号建议过小 | 新写正文改为 24–28px，空间不足时拆页，更新全部设计规范 |
| 成稿误用模板检查模式、输出文件名忽略时间戳 | 成稿检查 spec_lock，并使用实际导出路径 |
| 安装引导和依赖过重 | 使用真实仓库地址，区分核心依赖与可选工具，尊重 CC Switch 分发入口 |
| 单独安装 Skill 时根目录版权和素材声明被遗漏 | 在 Skill 目录保留与仓库一致的 LICENSE 和素材声明，测试防止漂移 |
| Windows 窄编码输出使有效模板被误报失败 | 质检输出提供编码回退；资产检查子进程使用 UTF-8 并保留失败诊断 |
| 缺少可重复验收 | 新增回归测试、全模板导出测试、离线资产检查及跨平台 CI |

## 验证与边界

- 全部 70 个模板 SVG 通过 canonical-authoring 模板模式检查，未发现缺失图片引用。
- 14 套 SVG 模板全部导出成 5 页 PPTX；ZIP 校验通过，每页包含原生文字，输出含嵌入图片。
- 13 套原生模板全部通过“2、1、2 页重排与重复，并逐页填写不同文字”的实际导出检查。
- 回归测试覆盖导出失败退出码、页序、重复副本独立性、无效页码、上下边界、组合形状及表格占位符、缺失图片和空模板库。
- 自动检查只能验证结构和估算版面；组合形状及表格的几何排版不在 review_pptx 的完整检查范围内。没有把本次程序化导出测试表述为 PowerPoint/WPS 的逐页视觉验收。
- 已查看仓库内三套精修模板的总览图；这不能替代新生成 PPTX 在演示软件中的渲染检查。
- 南强蔚蓝原始文件为旧式 PPT，仓库没有可用于原生填充的 PPTX。保留 SVG 路线；补齐原生路线需要合法可用的源文件，不以重绘文件冒充原始模板。
- 既有素材声明保持适用；本次不代表获得学校授权或完成素材权属核验。
- GitHub Actions 的跨平台结果以推送后实际运行结果为准，本地通过不代表远程 CI 已通过。

## 复现

```bash
python -m pip install -r skills/ppt-master/requirements-core.txt
python -m unittest discover -s tests -v
python skills/ppt-master/scripts/audit_xmu.py --check-svg --json .cache/xmu-audit.json
```

更改模板后需重跑以上命令。面向使用者交付实际演示稿时，另需检查全部页面的渲染、Logo、字体替换、内容真实性与讲者备注。
