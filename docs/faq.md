## 安装与运行

### 装完技能，Agent 里没出现 `/xmu-ppt`

1. 确认复制的是**整个目录** `skills/xmu-ppt/`，不是只有 `SKILL.md`；脚本、模板、工作流都在同级子目录里。
2. 确认目标路径是宿主认的目录（Claude Code 用户级 `~/.claude/skills/`，项目级 `.claude/skills/`；其他宿主见[工具目录](tools/README.md)）。
3. 开一个新会话再试——技能列表通常在会话启动时读取。
4. 仍然不行就走源码调用：直接在仓库目录里开 Agent，让它读 `skills/xmu-ppt/SKILL.md`，效果等价。

### 报 `ModuleNotFoundError` 或 `No module named 'pptx'`

Agent 用错了 Python。仓库里的脚本必须用装了依赖的那一个解释器跑：

```bash
# Windows
.\.venv\Scripts\python.exe skills/xmu-ppt/scripts/svg_to_pptx.py ...
# macOS / Linux
.venv/bin/python skills/xmu-ppt/scripts/svg_to_pptx.py ...
```

没建过虚拟环境时，按[快速开始](quickstart.md)创建 `.venv`，用它的解释器执行 `-m pip install -r skills/xmu-ppt/requirements-core.txt`，确保同时安装模板选择页需要的 Flask。

### 没有 Git 能用吗

能。下载 ZIP 解压后同样可用，步骤见[快速开始](quickstart.md)的「没有 Git」一节。只是后续更新要重新下载，不能用 `git pull`。

### 需要联网吗

依赖齐备后，原生填充和基础 SVG 导出脚本可以在本机执行。云端 Agent 的模型调用、网页查证、生图和部分配音服务仍可能需要联网。材料是否上传取决于所选 Agent 的运行方式与数据设置。

### 用哪个模型

本仓库的核心导出脚本不负责选择文案模型，内容与 SVG 排版由所选 Agent 完成。宿主需要支持文件读写和命令执行，并能持续遵守 Skill 工作流。不同模型的出稿效果需要结合你的材料验收。

## 出稿质量

### 生成的 PPT 里换行和我这边不一样

字体不同。仓库不附带字体文件，SVG 里写的字体栈在别人的机器上会回退。解决方式有两种：让全组统一安装同一套中文字体，或者把字少写一点、留出余量。**上台前一定用实际演示的那台电脑打开检查一遍。**

### 文字挤到边框或装饰上

说明文案超出了版式容量。两条路线的处理方式不同：

- **SVG 出稿**：内容页标题建议不超过 7 个汉字（42px 下再长会撞上 `PART 0X` 标签），正文单行不超过 42 字；超了就拆页，不要缩字号。
- **原生填充**，按文本框的实际宽高、字号和换行设置估算容量。单行槽位需要短文案，多行槽位可完整分行。分行后仍超出容量时，需要精简文案或换用容量更大的源版式。

### 能不能只给主题、不给材料

能，默认会写成方案或知识介绍稿。但它**不会**替你编实验结果、统计数字、参考文献和姓名——这类字段要么你给，要么留空。

### 一次要多久

时间取决于模型、输入材料、页数、出稿路线和复核次数。仓库目前缺少可复现的跨环境耗时基准。首次依赖安装和模板入库也会增加耗时。

## 模板与素材

### 为什么南强蔚蓝不能原生填充

它的原始文件是 `.ppt`，不是 `.pptx`，无法解析槽位。需要它时走 SVG 出稿；或先用 PowerPoint 另存为 `.pptx`，再用入库脚本重建索引。

### 能拿去商用或校外演示吗

代码与模板结构按 MIT 授权，校徽、校名标准字、校园照片及其他第三方素材的使用权需要另行核验。部分素材的再分发条件仍待确认，具体用途应按权利人的许可确定。[素材与许可](assets.md)。

### 模板里的「官方」是什么意思

是早期目录命名，指“按学校视觉规范精修重制”，**不代表学校出品或授权**。因为已被示例、命令和索引大量引用，改名会破坏现有用法，所以保留。

## 维护

### 怎么更新到最新版

```bash
python skills/xmu-ppt/scripts/update_repo.py
```

使用原始 Git checkout 中的虚拟环境解释器运行。脚本会检查已跟踪文件的未提交修改，通过 `git pull --ff-only` 更新，并同步核心依赖。首次运行、依赖变化或上次安装失败时会执行安装，成功后记录摘要。`--full` 跟踪并安装完整依赖，`--skip-pip` 跳过依赖安装。ZIP 与技能安装副本应通过原下载方式或安装器更新，先保留本地修改。

### 我改了模板，更新会不会被覆盖

`git pull` 会合并上游提交，本地修改与上游冲突时通常会中止。更新器会先拒绝已跟踪文件的未提交修改。自备模板可通过 `user_templates.py onboard` 放入独立本机目录，模板修改应先备份或提交到自己的分支。
